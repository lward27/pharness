# ASTRA M04: Registry upload interruption during measurement release

Status: the complete artifact set is verified after one bounded Node-runner retry; release observation and model qualification remain separate gates. The complete source build started at 15:43:38 UTC on 2026-09-08 and failed after 1,240 seconds at 16:04:18 UTC, while publishing the Node runner. Source is `e508f430e9f006c5f3e9f74fdd120d275605d85c`, builder `pharness-mac`, Docker context `rancher-desktop`, target Linux AMD64. Runtime, UI and Python runner receipts were emitted before the failure. No release pin or model evaluation had been dispatched at the time of the failure. The complete recovered artifact set was later verified and release PR 388 merged; no model diagnostic is implied by artifact completion.

The registry returned `blob upload unknown` after worker-node gateway errors: an upstream connection timeout at 16:01:53, a connection timeout and response-header timeout at 16:03:26, HTTP 504 responses, and a later PUT 404 at 16:04:18. A backend client-disconnected error followed the failed build. Initial anonymous write challenges and HEAD checks for absent layers are expected protocol steps and are not treated as credential failures.

The registry and both gateways were healthy, with zero restarts. The backend Pod had run since September 5. Argo was healthy and synchronized to GitOps `e66e8116c93c831baba65f521efab7bd14e24b4f`; the single registry backend and its existing upload-signing-key preservation were intact. During the bounded failure window, observed registry CPU peaked at 0.0408 cores, memory working set at 63.3 MB and throttled-period ratio at 0.0251. Those observations do not support a registry CPU/memory shortage as the cause.

The observed failure point is the worker-node gateway's upstream path. Intermittent connection or response loss is the leading hypothesis; the exact network/storage cause is unproven. The NetworkPolicies permit the identified gateway-to-registry flow. No Cilium daemonsets were found in the configured networking namespace, and no Hubble packet/flow evidence was collected. Both gateway paths subsequently passed twelve read-only `/v2/` probes each, with maximum observed latency below 0.26 seconds. These small probes do not reproduce large uploads.

The gateway uses Nginx's default upstream timeouts. Nginx documents the response-read timeout as an idle interval between reads. Because this incident also includes failures establishing connections, changing the read timeout alone would not explain or establish a repair. [Nginx proxy timeout documentation](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_read_timeout).

No policy, credential, TLS, endpoint, resource limit, workload or registry data was changed. One recorded retry of the failed Node runner passed in 81.168 seconds, from 16:15:26 to 16:16:47 UTC, using the same clean, frozen source and selected builder. It retains a fresh uncached AMD64 execution preflight and normal registry verification. The original failed operation and three completed image receipts remain separate; any recovered artifact set must still contain all seven verified images and the native bundle before a release can proceed.

During the subsequent evaluator publication, the worker-node gateway logged another PUT connection timeout to `10.43.146.139:5000` at 16:25:07 UTC. Twenty new-connection reads through the Service IP and exact backend Pod IP passed across the two gateways. Read-only TCP snapshots found no listener/backlog drops; the remote gateway has lifetime SYN-retransmission counters, which cannot by themselves attribute this incident. [The follow-up probe](ASTRA-MEASUREMENT-ALIGNMENT-REGISTRY-UPSTREAM-PROBE.json) and [TCP snapshot](ASTRA-MEASUREMENT-ALIGNMENT-REGISTRY-TCP-SNAPSHOT.json) retain this evidence. No further build retry or infrastructure change was made.

The successful retry demonstrates recovery of that component, not a permanent repair of the intermittent upstream failure. A repeated failure requires further targeted diagnosis; it must not trigger an unbounded retry or a broader network-policy change. Model limits, qualification thresholds, hosted activation and human Finance production approval remain unchanged.
